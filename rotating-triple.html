Rotating Triple-Sig Accounts on Algorand

An Algorand account type protected simultaneously by lattice Falcon-1024, hash-based two-layer SLH-DSA and elliptic-curve Ed25519 signatures, all three hidden until use. Each confirmed transaction atomically rotates authority to a fresh set of keys.

hidden key / approved exposed key / rejected Ed25519 (elliptic curve) Falcon-1024 (lattice) SLH-DSA (hash-based)

  1. Three signatures on every outgoing transaction

    Every outgoing transaction requires signatures from three different families of cryptography. Even if two schemes are broken, the third still protects the account. All three keys come from a single seed. Falcon-1024 is the core scheme, at NIST security category 5, the highest. Two-layer SLH-DSA and Ed25519 provide additional protection.

  2. A new key set on every transaction

    Each confirmed spend rekeys the account to a new stage with fresh Ed25519, Falcon-1024 and SLH-DSA keys. A stage key usually signs only one transaction, so the SLH-DSA key uses the FIPS 205 construction with a non-standard, shorter two-layer hypertree, which still gives room for the occasional retry. The account’s address stays the same. Rotation changes its authority without moving its remaining funds or assets to another account.

  3. Invisible at rest

    The next stage’s program and its fresh Ed25519, Falcon-1024 and SLH-DSA public keys stay off chain until it signs. Its authorizer address is a 32-byte hash. No public key carries over from an earlier stage.

  4. Revealed on use, retired on confirmation

    Broadcasting a transaction reveals the live stage’s program. When it confirms, authority moves to fresh Ed25519, Falcon-1024 and SLH-DSA keys. The old program remains public but can no longer authorize the account. If the transaction fails or expires, the exposed stage stays active until another rotation confirms.

  5. Three signature checks

    A forged spend must pass all three signature checks while the stage still controls the account. SLH-DSA is stateless, so retries and a restored signer need no record of earlier attempts, and signing the same transaction again gives the same signature. Its margin shrinks only gradually with the number of distinct transactions one stage signs. A stage normally signs one; the design assumes at most 65,536.

  6. No stateful application to deploy

    Authorization uses Algorand’s stateless Logic Signatures. Each verification program travels with the transaction, so there is no stateful application to deploy. The transaction still carries the program, signatures, supporting transactions and fees.
