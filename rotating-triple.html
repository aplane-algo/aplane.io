Rotating Triple-Sig: A better bunker?

An Algorand account type that keeps its three public keys out of sight until use and then swaps them out for fresh ones on every transaction.

  1. Three keys on every transaction, not one

    Each of its transactions is protected by three keys from three unrelated families of cryptography. All three must sign. Even if two of those schemes were broken, the third would still protect the account.

    Falcon-1024 · latticeWOTS · hash-basedEd25519 · elliptic curve

  2. A new key set on every transaction

    The three-key set is replaced on every transaction by a rekey, built into the transaction itself. No two transactions use the same set of keys. The account’s address, balance and assets never move.

  3. Invisible at rest

    Even after a key set has been rotated in, its public keys stay off chain until it signs. All the chain holds is a 32-byte hash. There is nothing for an attacker to target.

  4. Visible only as it is retired

    The live key set becomes visible on chain only when a transaction is submitted. Once that transaction is final, usually within about 3 seconds, the key set is obsolete: the same transaction has already rotated in a new live set that nobody has seen.

  5. Three breaks, one round, and a race

    When a transaction is submitted and its public keys are exposed, an attacker would need to break all three keys within the roughly 3-second round in which they are still live, and get a forged transaction finalized before the real one.
